# Local model adapter — 2026-10-13

`AI_PROVIDER=ollama` supports explicitly configured numeric HTTP loopback endpoints for chat and selected-file coding proposals. It reuses the bounded compatible transport and existing session, current policy, inference queue and dispatch authorization. No provider credential is read or sent. Remote addresses, credential/query/fragment URLs and redirects are rejected. Endpoint validation runs after queue acquisition and before dispatch. No cloud or deterministic fallback is supplied for this adapter.

The owned HTTP client ignores environment proxies (`trust_env=False`). Independent review reproduced external HTTP_PROXY routing in the first implementation; the fix and production-client-construction regression closed that High finding. The regression inspects real HTTPX routing with HTTP_PROXY/ALL_PROXY present and NO_PROXY empty before substituting a fixture transport; no network request is sent. Independent closure: PASS, 45 focused provider/queue tests passed.

Transport contract tests are not live model proof. The download/benchmark script uses an owned standalone Ollama server, isolated profile, `OLLAMA_NO_CLOUD=1`, one CPU model and disposable application persistence. It approves only the exact pure-addition AST parsed from the file's actual UTF-8 bytes. Live acceptance remains pending until the downloaded model produces a valid diff and actual approved test/apply/rollback commands succeed.

Loopback restricts this backend's destination; it cannot establish what an arbitrary separately configured local server does afterward. An unmanaged server may relay requests or enable cloud models. Such a server is not accepted as proof of local-only execution. Packaged managed-runtime supervision and configuration verification remain M3 work. No global Ollama service, user model configuration or real user database was changed.

The wire API is Ollama's documented [compatible chat completions interface](https://docs.ollama.com/api/openai-compatibility). Selected local model availability/quality must be verified separately. The adapter supports text proposals; the structured task-planning provider selection is unchanged.
