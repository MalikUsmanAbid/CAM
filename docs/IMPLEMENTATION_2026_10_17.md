## Continued code: owned UIA, encrypted export and runtime assembly

- Extended Windows owned-process supervision with bounded private stdin, a two-process/384 MiB worker job (to include a frozen bootloader), bounded output, sanitized environment and cooperative cancellation. Input text travels over explicitly inherited pipes rather than argv or temporary request files. Existing command calls keep their original no-stdin contract.
- Added a standalone UIA worker plus backend adapter and gated dashboard controls. It binds exact visible windows to process creation time, same user/session and non-elevated token checks. Controls bind runtime identity, type, bounded label/automation ID and geometry. UIA Invoke/SetValue use provider patterns with identity rechecks; global keyboard/pointer injection, password fields, cross-process controls and elevated windows are unsupported. Observation is bounded, untrusted data. Calls returning are not proof of application-level success or reversibility.
- Added actor-owned ephemeral sessions, serialized observations/actions, stale-observation rejection, one-shot observation use after effects and cleanup of active owned workers. Durable operation IDs/contract hashes and uncertainty state use additive migration **10**, source only. Restart marks dispatching UIA records uncertain. Cancellation/timeout cannot undo an already accepted external effect; identical operation IDs cannot be blindly dispatched again. Raw typed text and titles are excluded from this ledger. Production enablement remains explicitly false until Windows acceptance; there is no environment bypass.
- Added backend and frontend source cases for private-pipe input, actual fixture process termination on cancellation, exact Invoke pattern invocation, last-boundary control identity replacement, actor changes, synchronized observation/action races, uncertainty persistence/duplicate prevention and disabled production UI. These fixtures are not live Windows UIA acceptance.
- Corrected a source-discovered draft snapshot bug: multi-destination scopes permit exact reads, while the snapshot tool had been classified as an edit. Snapshot capture now binds each read destination under a high-risk read approval, and independently checks current edit policy before retaining the editable internal snapshot. Added executor-level source regression proving approval creation/consumption and both destination bindings. No old approval is reused across a changed tool contract.

Secrets/ciphertext have bounded in-memory capacity, stop/shutdown cleanup and cooperative worker joining before temporary ownership is released. Python/browser memory does not guarantee zeroization. The running database is never restored or migrated by this flow.
