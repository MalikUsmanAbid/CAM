## Code added and connected

- **Desktop:** native Tauri source, inherited-pipe session bootstrap, suspended/Job-contained Python process launch, restricted packaged-window IPC, tray Show/Exit, explicit portable data root, credential-free local model settings, Python sidecar specification and an explicit installer/portable assembly script. Native dependencies/toolchain and packaging are still unverified. Saving model settings takes effect on next application launch. Session expiry currently requires relaunch.
- **Agent jobs:** migration-backed role inputs, dependencies and outcomes; atomic competing claims; case-normalized coder file claims; two bounded role slots sharing the existing one-inference transport gate; existing ToolExecutor dispatch. Coordinator/researcher produce analysis, coder proposes a patch, and reviewer receives bounded actual stored change/command evidence. Truncated/omitted evidence cannot establish a clean review. No automatic apply, test command, commit or publish is introduced.
- **Agent cancellation:** approval previews carry the job identity, inherited dispatch callbacks are preserved, and generic continuation routes through the job claim/state checks. A cancelled job cannot reuse its approval through generic Continue. Restart marks interrupted work rather than dispatching it with stale session authority.
- **Knowledge/artifacts:** exact source-hash import approvals; shared project file exclusions; bounded snapshot search with source references; immutable text artifact versions and stored source lineage. These are literal text snapshots, not embeddings, live browsing or verified factual conclusions. Export currently uses the existing Coding Studio create-file workflow, not an automatic file write.
- **Decisions/reminders:** scoped one-answer questions, timezone-aware due dates, durable unique occurrence IDs, duplicate-tick protection, one summarized missed occurrence per repeating schedule, cancellation and an authenticated notification inbox. Task-review reminders do not execute tasks; acknowledgement does not authorize execution. Existing legacy schedule-record endpoints remain compatible and separate.
- **Control:** persistent emergency stop blocks tool/model dispatch and advances policy revision, preserving user category settings. Cooperative jobs/actions are cancelled; browser/computer sessions receive cleanup requests with an incomplete-cleanup result if they do not finish within the bound. This does not undo accepted external actions or provide native process/network isolation. Browser execution remains disabled.
- **Skills/accounts/work:** declarative project manifests reference existing available tools, cannot lower risk, install disabled and require explicit activation. Updates require a higher version and reset activation. Account configuration accepts backend-vault references and explicit consent. Email/GitHub adapters use fixed official endpoints, disable environment proxies/redirects, bind account revision and exact payload, and record one operation ID before dispatch. Uncertain outcomes cannot be blindly retried with that ID. No real account was connected or contacted. Business leads/proposals/orders/follow-ups/content drafts support scoped records and optimistic revision checks.
- **Voice:** capture starts only on a user's hold, stops/releases tracks, bounds duration/memory, discards late permission results and supports interruption. Pending audio is memory-only, session-bound and expires; approval records contain only an opaque capture reference/hash. Transcription requires explicit `JARVIS_STT_ENABLED=1` plus a numeric loopback `JARVIS_STT_ENDPOINT`. An unmanaged loopback service may relay data; locality is not proof of its behavior. Desktop's sanitized child environment does not yet expose a voice endpoint configuration, so packaged transcription remains unavailable until that setup is added. Installed local speech voices are selected explicitly; no remote voice fallback.
- **Recovery:** `python -m scripts.manage_backup create --database <explicit-db> --output <absent-file>` uses SQLite backup and strict schema/integrity/hash checks, with a 32 MiB database bound. The default bundle is unencrypted. `--windows-user-encryption` uses DPAPI tied to the current Windows user/machine. Credentials, project worktrees and model weights are excluded. `restore --bundle <file> --new-directory <absent-local-directory>` creates a fresh data directory and never replaces the active database or migrates it. Existing project paths may need re-registration. Cloud backup with a portable recovery key is not implemented.
- **Release recipe:** `python -m scripts.build_desktop --output-directory <absent-directory> [--cargo <explicit-cargo-exe>]` is source for the later build stage. It requires MSVC, PyInstaller and cargo-tauri; installs nothing, refuses an existing generated sidecar, builds the frontend/native installer, and assembles a hash manifest and portable ZIP. It does not sign or acceptance-verify artifacts. Portable WebView2/model prerequisites remain explicit; no installer or ZIP was produced in this increment.
